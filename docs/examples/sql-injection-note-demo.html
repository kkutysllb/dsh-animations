SQL 注入漏洞笔记

#Web安全 #OWASP-Top1 #注入类 · 复习 ×3 · ⭐⭐⭐⭐⭐

一、一句话原理

用户输入被直接拼进 SQL 语句，攻击者用输入改变语句结构——数据与代码的边界被打破。

二、危险写法（登录绕过）

❌ 漏洞代码 · 字符串拼接
String sql = "SELECT * FROM users WHERE name='" + username
    + "' AND pwd='" + password + "'";
// 输入：admin' --  → 密码条件被注释，直接登录！

三、修复方案

✅ 参数化查询 · 预编译
PreparedStatement ps = conn.prepareStatement(
  "SELECT * FROM users WHERE name=? AND pwd=?");
ps.setString(1, username); ps.setString(2, password);
// 参数只当"数据"，永不参与语法解析
  • 参数化查询是根治手段；ORM（MyBatis #{} / SQLAlchemy）默认安全
  • 最小权限：应用账号禁 DROP / FILE 等高危权限
  • 纵深防御：输入白名单校验 + WAF + 报错信息脱敏
⚡ 实战口诀：所有外部输入都是不可信的——拼接处即注入点，凡是 SQL 就要预编译。
📌 记忆卡：单引号探测 → 注释符(-- #)截断 → UNION 联合查询 → 时间盲注(sleep)。修复三板斧：预编译、最小权限、白名单。
