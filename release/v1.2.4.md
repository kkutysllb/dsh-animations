## 一、修复：dsh `0.2.1-alpha.1` 下插件被兼容门静默禁用

- **现象**：升级到上游 `dsh-v0.2.1-alpha.1`（2026-10-03 prerelease）后，插件不再被加载；
  app-boot 兼容闸门只在 stderr 留一行 `disabling profile plugin …` /
  `skipping profile bundle`，界面无任何提示。
- **根因**：5 条 `peerDependencies` 的上界 `<0.2.0` 对运行时 `0.2.1-alpha.1`
  求值为 **false**。该范围设计于 0.1.7 世代，只在 `0.2.0-rc.*` 下侥幸成立
  （semver 里 `0.2.0-rc.2 < 0.2.0`），上游跨过 `0.2.0` 边界即失配。
  检查器只看 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*` 前缀的 peer，
  按 `semver.satisfies(..., { includePrerelease: true })` 评估。
- **修复**：5 条 peer 的上界统一改为 **`<1.0.0`**（`@deepseek-ai/dsh` +
  `@deepseek-ai/dsh-client-locale` + `-ui-slots` + `-ui-conversation` + `-ui-workspace`）；
  `peerDependenciesMeta` 保持**全部 optional**（安装面零污染是硬要求，不动）。

## 二、兼容性与升级说明

- **纯声明层改动**：只动 `package.json` 的 5 条 peer 范围与版本号；
  `lib/client.js`、8 个动效技能、能力通告、双通道 manifest（`dsh`/`qilin`）、
  槽位注册（`sidebar.panellist` / `main`）**全部不变**；
- **放宽是向后兼容的**：旧范围覆盖的 `0.1.0-rc.5` → `0.2.0-rc.2` 仍在新范围内，
  故对现网 KCoder（0.2.0-rc.2）无行为变化；
- 升级即替换包体，无需迁移。

## 三、验证

- `node scripts/smoke-plugin.mjs` **全绿**（含 5 条 peer 范围断言、prerelease 比较器断言、
  `optional` 断言、`release/v1.2.4.md` 对账）；
- 语义实测（semver 7.8.5，`includePrerelease: true`）：
